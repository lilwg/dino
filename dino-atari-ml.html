How it works

The Atari 2600 has a 1.19 MHz 6502 CPU, 128 bytes of RAM, and 4 KB of ROM. There is no floating-point unit and no multiply instruction. The CPU spends most of its time generating the display scanline by scanline, leaving roughly 2,048 cycles per frame for game logic.

Q-Table uses tabular Q-learning with 32 discrete states and 3 actions. The entire Q-table fits in 96 bytes of RAM, leaving 32 bytes for game state and scratch space. It learns from scratch by playing — crank up the speed slider to watch it go from random to superhuman in under a minute. All updates use only addition, comparison, and bit-shifts — no multiply needed.

Neural Net runs a pre-trained 4→4→3 feedforward network quantized to 8-bit integer weights. The 35 weight bytes live in ROM. The forward pass requires 28 multiply-accumulate operations. Using a 512-byte multiply lookup table in ROM, each MAC takes ~30 cycles, for a total of ~840 cycles per frame — well within the VBLANK budget.

Rules is a simple ball-tracking heuristic for comparison. It requires almost zero computation but demonstrates that even the simplest “AI” can be effective at Pong.

Could this really run on Atari hardware?

Inference: Yes. Both the Q-table lookup and the quantized neural network fit comfortably within the Atari 2600’s constraints. The Q-table needs 96 bytes of RAM and a handful of cycles for a table lookup. The neural network stores 35 bytes of weights in ROM and computes a forward pass in ~840 cycles using a lookup-table multiply.

Learning: Partially. Q-learning updates require only addition and bit-shifts, so the Q-table agent could genuinely learn on-hardware. The update takes ~200 cycles per step. However, training a neural network with backpropagation is infeasible — there is not enough RAM for gradient buffers, and the multiply-heavy computation would blow the cycle budget. The practical approach is to train offline and burn the quantized weights into ROM.
